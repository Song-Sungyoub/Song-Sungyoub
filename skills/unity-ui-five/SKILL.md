# Unity UI Five

5팀의 Unity UI 구성 지침이다. 작업 대상의 디자인과 기존 컨트롤을 유지하며, 프로젝트 전체를 불필요하게 개편하지 않는다.

## 사업별 기준 우선

- **글꼴은 사업마다 다르다. 다른 사업이나 참고 화면의 폰트를 가져와 적용하지 않는다.** 대상 화면의 지정 폰트·대체 폰트·굵기·크기를 우선하며, 기준이 없으면 기존 화면을 확인한다. 결정할 근거가 없을 때만 확인을 요청한다.
- 색상, 로고, 아이콘, 여백, 모서리 크기와 CanvasScaler 설정도 대상 사업 기준을 따른다. 참고 화면의 테마·색상·해상도를 공통 필수값으로 취급하지 않는다.
- UI 목업만 요청받았다면 통신·API·인증·업무 스크립트는 변경하지 않는다. 기존 스크립트가 UI를 덮어쓸 가능성은 확인하고 결과에 알린다. 별도 승인을 요구하는 저장소 규칙은 그대로 따른다.

## 권장 패널 계층

화면·패널·카드는 다음 계층을 기본으로 구성한다. 각 영역의 역할이 같으면 이름도 일관되게 유지한다.

```text
Panel
├─ Background          ← 배경·테두리 Image
├─ Title               ← 제목 영역
│  └─ Text             ← 제목 TMP 텍스트
└─ Content             ← 실제 내용·입력 컨트롤·반복 항목
```

- `Panel`: 영역의 크기와 외부 배치 기준을 담당한다.
- `Background`: 부모 영역에 맞춰 Stretch하고 콘텐츠 뒤에 배치한다. 장식 배경은 Raycast Target을 끈다.
- `Title`: 제목과 필요한 제목 영역의 컨트롤을 묶는다. 제목이 없으면 생략한다.
- `Content`: 실제 컨트롤과 하위 패널을 배치하며, 반복 묶음에 필요한 LayoutGroup과 간격을 설정한다.
- 부모 LayoutGroup이 Title과 Content를 배치할 때 Background는 LayoutElement의 Ignore Layout으로 배치 계산에서 제외한다.
- 단순 패널은 `Panel` 자체에 배경 Image를 두고 별도 Background를 생략해도 된다. 작은 버튼·라벨까지 이 계층을 반복 생성하지 않는다.
- 기존 화면을 수정할 때는 이름 변경으로 스크립트의 경로 탐색이나 참조가 끊기지 않는지 확인한다. 이 규칙만을 위해 승인 범위 밖의 기존 계층을 일괄 변경하지 않는다.

## 구성 원칙

1. **배경과 콘텐츠 분리**
   - 패널·버튼 배경은 Image, 표시 문구는 자식 TMP 텍스트, 사용자 입력은 실제 InputField·Button 등으로 구성한다.
   - 합성 이미지에 포함된 입력 안내·버튼 글자·상태를 분리할 때 밑그림이 남아 중복 표시되지 않게 한다. 로고와 장식은 이미지로 유지할 수 있다.
   - 기존 입력 필드, 버튼, GameObject 식별자와 직렬화 참조를 가능한 한 보존한다.

2. **공용 Sliced Image 우선**
   - 대상 프로젝트의 공용 Sprite를 먼저 찾는다. 둥근 배경은 Rounded Rect 같은 9-slice Sprite와 Image.Type.Sliced를 우선 검토한다.
   - Sprite Border, Pixels Per Unit, Image의 Pixels Per Unit Multiplier와 실제 크기를 함께 확인해 모서리를 맞춘다. 외곽·내부 Image를 겹쳐 테두리를 구성할 수 있다.
   - Sliced Image로 필요한 외형을 표현할 수 있다면 별도 모서리 효과 컴포넌트는 추가하지 않는다. 다만 기존 효과를 바꾸는 것은 승인된 범위와 시각적 이득이 있을 때만 한다.
   - 외부 라이브러리나 패키지는 UI 외형만을 위해 새로 설치하지 않는다. 다른 경로의 동일 GUID 에셋을 무조건 복사하지 않는다.

3. **배치와 크기 책임 구분**
   - 반복 행과 가로·세로 묶음은 Horizontal/Vertical LayoutGroup, LayoutElement를 활용한다. 고정 목업 좌표가 필요한 부분은 RectTransform을 유지한다.
   - ContentSizeFitter와 부모 LayoutGroup이 같은 축의 크기를 서로 제어하지 않도록 한다.
   - Viewport, Mask/RectMask2D, ScrollRect 및 Anchors를 실제 화면 크기에 맞춰 확인한다. 장식·텍스트의 Raycast Target이 입력을 가로막지 않게 한다.

4. **반복 요소와 목록 재사용**
   - 같은 행·카드가 반복되면 의미 있는 단위의 프리팹 또는 기존 템플릿을 재사용한다. 단순 행마다 Presenter를 만들지 않는다.
   - 기존 표 컴포넌트가 있고 열 기반 표가 요구되면 헤더, Viewport, Content, 행·셀 템플릿 구성을 확인한다. 버튼이 포함된 카드형 목록까지 표로 강제하지 않는다.
   - 데이터 가상화·풀링·정렬·컨텍스트 메뉴는 요청이나 실제 데이터 규모에 필요할 때만 추가한다. 데모 데이터 생성기를 제품 화면에 연결하지 않는다.
   - 동작을 연결하는 작업에서는 대상 프로젝트의 화면 MVP 구조를 따르며, 목업만을 위해 업무 계층이나 인터페이스를 추가하지 않는다.

5. **저장 후 실제 화면 확인**
   - Unity Editor 도구 또는 Editor API로 편집하고, 프리팹 저장·재임포트 후 인스턴스의 배치와 참조가 유지되는지 확인한다.
   - 원본과 같은 조건에서 렌더링해 문구, 위치·간격, 색상, 모서리·테두리, 텍스트 잘림 및 중복 이미지를 비교한다. 가능한 경우 크기가 달라졌을 때도 확인한다.
   - 입력 필드와 버튼은 실제 컨트롤이 있는지 확인한다. 값 대입 검사는 실제 키보드·마우스 검증과 구분한다. 목업 검증을 이유로 인증·삭제 등 업무 동작을 실행하지 않는다.
   - 변경 파일, 재사용 요소, 수행한 검증과 남은 외형 차이·기능 미연결을 보고한다. 정적 렌더링만 했으면 Play 모드 동작까지 검증했다고 쓰지 않는다.

## 참조 자료의 취급

- 현재 프로젝트에서 제공된 공용 에셋과 디자인 자료만 필요한 범위에서 확인한다. 참조 프로젝트는 별도 요청 없이 수정하지 않는다.
- 오브젝트 이름이 Button이어도 실제 Button 컴포넌트가 있는지 확인한다. 외형 예시를 동작하는 컨트롤 완제품으로 취급하지 않는다.
- 이 스킬에 회사명, 고객명, 내부 프로젝트명, 비공개 저장소 주소, 내부 파일 경로, 계정 정보나 인증 정보를 추가하지 않는다. 예시는 일반적인 UI 용어만 사용한다.
